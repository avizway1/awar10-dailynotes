

ArgoCD helps us to deploy our application into K8s. 

--> It act as "single source of truth". 
--> A git repo act as source of truth to deploy our application. If we manually deploying using kubectl apply, its hard to track who applied what changes.
--> When using Argo, all manifest files has to push to git repo, argo will pick from there and deploy to k8s.

1. Declarative 
2. Versioned in Git
3. Pulled automatically : An agent inside the cluster pull the changes. (PULL.. NOT PUSH)
4. Continuosly reconciled : The agent keeps comapring and correcting. 

PUSH based : Jenkins / Github Actions (jenkins/GHA --> EKS Cluster)
PULL based : GitOps with ArgoCD (gitrepo  <--  ArgoCD inside EKS) - comapre and pull

---

ArgoCD Components: 

argocd-server : The front desk. Serves Web UI, CLI. handles the login and RBAC.

argocd-repo-server : Clones the git repo and turns it into plain YAML. 

argocd-application-controller : The brain of Argo. It compares rendered YAML with live resources and applies the changes. 

argocd-redis : Cache so git and cluster wont utilise its full resources for every refresh.

dex-server : SSO broidge for github, okta, aws iam identity center

applicationset-controller : Generates many applications from one template.
