Invocation Models for Lambda fucntion:

Synchronous Invocations : The caller (LB, APiGateway, Function URL) sends the request for a response, Lambda runs the function and return the result directly to the caller. 
--> If the lambda funciton fails, The caller is responsible for retrying..

Asynchrounous Invocations :  The caller (SQS, SNS, Eventbridge, S3) sends the request for a response, Lambda return with status code 202, then starts the run process and sends the result to the caller. If the function fails, it send the event to DLQ (Dead letter Queue) and retries 2 times..

Event Source Mapping : Lambda polls the source for new records at services (SQS, DynamoDB, MSK Kafka), And invokes the lambda function when it finds new records.. We can invoke for a batch of msgs..

Scheduled or Event based is possible using EventBridge service..

============

Lambda function has 3 Phases in lifecycle:

lambda_handler : THis is the entry point to the lambda function.

1. INIT Phase : Initilisation phase : Downloads the code, initilise the runtime to run the code..
2. INVOKE Phase : Executes the handler function. THis is active phase (Code run / Business logic)..
3. SHUTDOWN Phase : After a period of inactivity, AWS destroys the environment and free the resources..


cold start : INIT + INVOKE : First invoke or after long time if you invoke any inactive lambda function, get high latency as you are using it after long time.

warm start : INVOKE Phase Only : Environment will be available to run the code.. Low Latency..

How to reduse cold start time : 
--> Provisioned cuncurrency
--> SnapStart **

AWS Lambda SnapStart is a performance optimization feature designed to reduce "cold start" startup latency by up to 10 times at no extra cost
