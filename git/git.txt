TBD : Trunk Based Development: it is a GitHub Git development strategy. We generally don't work on the main branch directly. We always create a branch. We do all the changes in the branch. Once the feature development is completed we merge the code into the main branch 

a version control management practice where all developers merge small, frequent updates into a single central branch, typically called the "trunk" or "main"


git branch 	: Displays in which branch we are currently working. 


git branch feature-x		: Creates a branch with the name `feature-x`. 

git checkout feature-x		: Switch to featurex branch, traditional command. 
git switch feature-x		: Switch to feature-x branch and this is a modern command. 

git switch -c feature-x		: Create a branch and switch to that branch automatically. 
git checkout -b feature-x	: Create a branch and switch to that branch automatically.

git rebase : `git rebase` generally rewrites all the changes. It is not a recommended approach for shared repositories. This works best in our local commits.

Thumb rule when working with rebase: never rebase a branch that has been pushed to a shared or public repo. For local development absolutely fine to use this rebase. For central or shared repositories always use `git merge`, as rebase cleans up the history and it may overwrite others' work.

git stash : To temporarily save uncommitted code changes without committing them. 

You can assume a scenario where you are working on a feature and that feature development is half completed but your team member asked you to switch to a different branch to fix a mission-critical issue. You are in a situation where you cannot commit now but you need to switch to other branches to fix the critical bug. 

echo "Commit-1 Feature 1 setup" >> C1.txt
git add . && git commit -m "Commiting C1 feature"

echo "Commit-2 Feature 2 setup" >> C2.txt
git add . && git commit -m "Commiting C2 feature"

echo "Commit-3 Feature 3 setup" >> C3.txt
git add . 

--> Not in position to commit the changes


git stash					--> Stash the uncommited changes
git stash show -p			--> Shows the stashed content	
git stash push -m "msg"		--> Stash changes with a msg
git stash list				--> List all stashed changes
git stash apply				--> apply and keeps the stash
git stash pop				--> apply and deletes the stash
