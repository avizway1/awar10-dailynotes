S3 : Simple Storage Service : 

Its an Object based storage, You can store anything, it treat as Object. 
We can store flat files. 

bucket is nothing but a folder or directory with unique namespace across the globe or within account..

Global namespace : By default, S3 bucket names are unique across the globe. 

Account Regional Namespace : unique within your account, AWS make it unique by adding suffix to the names. 

General purpose : Recommended for most use cases and access patterns. General purpose buckets are the original S3 bucket type. They allow a mix of storage classes that redundantly store objects "across multiple Availability Zones".

Directory : Recommended for low-latency use cases. These buckets use only the S3 Express One Zone storage class, which provides faster processing of data within a "single Availability Zone".

How to make an Object Public in S3.? 

1. Account level block public access : OFF by default.. 
2. Bucket level public access : Specific to bucket : Block all public access: On --> off
3. Object Level: 

--> Using ACLs : Access Control List
--> Using Bucket Policy


step 1 : verify account level
Step 2 : verify bucket level
	2.1 Block all public access: off
	2.2 permisisons --> Object Ownership --> edit --> enable ACLs
Step 3 : choose object and make public using ACL.

* THis method has a limitation, If we overwrite with new verison, we need to make public again.

Access Pattern : 
1. How frequently you are accessing the data.?
2. Do you need data without delay.? or you are okay to access with delays.?

S3 Standard : Frequently accessed data can be stored here. 
--> We can access data immediately. 
--> Data automatically spans across multiple AZs (>=3 AZs)
--> 99.99% Availability.. 99.999999999% Durability (11 9's).. 

Yearly (365 days): 52 minutes 36 seconds downtime expected for 99.99% Availability..

Standard-IA (Infrequently Accessed) : 
--> THis is designed to store less freq accessed data.  (less cost than S3 Standard)
--> We can access data immediately. 
--> Data automatically spans across multiple AZs (>=3 AZs)
--> 99.99% Availability.. 99.999999999% Durability (11 9's).. 

One Zone-IA (Infrequently Accessed) : 
--> Store easily reprodusable data.. 
--> THis is designed to store less freq accessed data.  (less cost than S3 Standard)
--> We can access data immediately. 
--> Data stores only in one AZ
--> 99.95% Availability.. 99.999999999% Durability (11 9's).. 


Glacier Instant Retrieval : 
--> Long-lived archive data accessed once a quarter with instant retrieval in milliseconds

Glacier Flexible Retrieval (formerly Glacier) : 
--> Long-lived archive data accessed once a year with retrieval of minutes to hours
--> We cannot access data immediately. 
--> We need to perform data retraival to access the data. 

Glacier Deep Archive :
--> Long-lived archive data accessed less than once a year with retrieval of hours

Intelligent Tier: 
--> when we dont have clarity on data access patterns. 
--> freq changing data access requirements. (unknown access patterns)


Bulk retrieval : Typically within 5-12 hours.
Standard retrieval : Typically within 3-5 hours.
Expedited retrieval : Typically within 1-5 minutes when retrieving less than 250 MB.

versioning: enable Bucket Versioning to help protect against unintentionally/Accidental overwriting or deleting objects.

Without Versioning:  
--> if you edit file and uplaod multiple times with same name, we can see/get only most recently uploaded file. We cannot track changes happening on the file.
--> If we delete, We cannot get the object back. it permanently deletes.

With versioning:
--> if you edit file and upload multiple times with same name, we can see/get all uploaded files. We can track changes happening on the files.
--> When versioning is set to hide, You get a delete marker... Delete the delete marker, to get the object back.


Delete : we get a delete marker, Delete the delete marker to get the object back.
Permanently delete : Deletes completely, No recover option.

S3 Life Cycle Configuration Management Rule : LCR : 
--> This feature helps us to transit data from one storage class to another storage class. 
--> It also, helps us to delete data automatically.
--> We can apply one transition for "current versioned" objects.
--> We can apply another transition for "Previous versioned" objects.
--> We do have option to exclude a particular version (most recent-1) from transition.. 

===================


Replication option: 

SRR : Same Region Replication : Source and dest buckets should be in same region
CRR : Cross Region Replication : Source and dest buckets should be in diff region

--> Source bucket and destination bucket should enable with versioning. 

* If our source bucket has some existing data, The Replication rule cannot replicate it.. We need to create a batch job.. or use sync command to replicate exiting data.. 

--> Data automatically replicates after the replication creation. Existing data wont be replicate. use sync and then configure CRR/SRR.
